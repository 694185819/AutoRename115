# 架构优化大纲与进度

> 目标：不让搜索/命名的判断逻辑继续堆在单个巨型函数里，做到"出问题能逐层定位"。
> 原则：**小步重构、每步回归全绿，不推翻已稳定的季集/NFO/字幕规则。**

## 0. 基线（重构前，2026-10-28）

| 指标 | 数值 |
|---|---|
| 离线回归 | **64 通过 / 1 失败**（`test_gui_real_listing` 依赖实时网盘返回 36 项，现为 35 项，与本轮无关） |
| 模块 | 15 个，共 14602 行 |
| 最大模块 | `gui.py` 4258 行、`planner.py` 3361 行、`metadata.py` 2329 行 |
| 最大函数 | `MetadataClient.match()` 363 行、`_series_ops()` 245 行、`_build_ui()` 366 行 |

### 当前 `metadata.py` 的职责堆叠

```
MetadataClient
├─ 网络/缓存层      _request / _wait / _get_json / _cache_get / _cache_put
├─ 来源搜索        search_bangumi / search_douban / search_imdb / search_tmdb
├─ 来源详情        bangumi_detail / _details_* / tmdb_* (结构、英文名、反查)
├─ 匹配打分        _score / _anchor_titles / _candidate_matches_anchor / _pick_*
├─ 决策            resolve_ids / _series_identity / match()  ← 363 行
└─ 其它            normalize_country / _country_from_tags / fetch_image ...
```

问题：打分规则、锚点校验、季号修正、跨来源核对、ID 兜底全部在 `match()` 一个函数里；
出一次错配（如"剧版"命中 Big Hero 6、"假如是爱"污染《假如…？》）要从 363 行里逐段找。

## 1. 总大纲

| 阶段 | 内容 | 风险 | 状态 |
|---|---|---|---|
| A | 拆分 `match()`：来源适配器 → 打分器 → 决策器 | 中 | **完成** |
| B | 质量检查结果对象化（`QcResult`），替代字符串型"需确认/跳过" | 低 | **完成** |
| C | GUI 视图层解耦（`_build_ui` / `_handle` 按面板与事件路由拆分） | 低 | **完成** |

**不做**：重写 Planner、换框架、上数据库、拆 PyPI 包。
**理由**：季集/NFO/字幕/版本这些规则承载了十几个真实场景，重写等于把已修的 bug 再踩一遍。

## 2. A 阶段：搜索匹配分层

### A1 来源适配器 ✅

- 新增 `app/sources/__init__.py`：
  - `SourceAdapter` 协议：`search(query, media_type, season)` / `detail(sid)` / `identify(cand, media_type, aliases)`；
  - `register(name, factory)` + `build()` 注册表，供新增来源接入；
  - `ClientAdapter` 把 `MetadataClient.search_*` 包装成协议，现有四源零改动接入。
- **结果**：扩展点就位；四大来源的请求代码仍在 `MetadataClient`（渐进式迁移，行为不变）。

### A2 打分层 + 文本工具层 ✅

- 新增 `app/textnorm.py`（256 行）：`norm_title` / `titles_agree` / `strip_season_markers` /
  `candidate_season` / `fuzzy_queries` / `douban_title_parts` 等纯文本工具。
  原先它们在 `metadata.py`，抽出来后 `scoring.py` 不再反向 import `metadata.py`（消除循环依赖）。
- 新增 `app/scoring.py`（354 行）：`anchor_titles` / `candidate_matches_anchor` / `score` /
  `pick_primary` / `pick_imdb` / `candidate_is_animation`，无网络、无缓存、可直接单测。
- `metadata.py` 保留同名方法作为转发（`metadata.py` 2329 → **1835 行**），调用方零改动。
- 新增 `work/tests/test_scoring.py`（9 个用例）：锚点分段、弱锚点拒绝、短锚点精确、
  OAD 降权、partial 打折、季号加权、文件季号剔除类别名、IMDb 精确优先、动画标记。

### A3 决策器 ✅

- 新增 `app/decider.py`（389 行）：
  - `dedupe()` 同来源同 ID 去重；
  - `apply_category_bias()` 动画区/电视剧区加权；
  - `filter_by_anchor()` 锚点过滤（记录被淘汰的无关候选）；
  - `filter_by_movie_year()` 电影年份消歧；
  - `decide()` 主结果挑选 + 跨来源核对 + 标题/ID/地区/动画/置信度；
  - `identify_series()` 季条目主剧还原（主剧名/首播年/主剧 IMDb）。
- `MetadataClient.match()`：**363 行 → 12 行**，只做编排：
  `search_pool()`（搜索阶段，原样迁出）→ `decider.decide()` → `decider.identify_series()`。
- `metadata.py`：2329 → **1556 行**。
- 新增 `work/tests/test_decider.py`（8 个用例）：精确压近似、锚点过滤、跨源核对、
  主剧还原、无季号不走还原、电影年份过滤、去重、分类偏向。
- 修掉一个拆分中引入的顺序问题：`decide()` 原先在打分前过滤，导致裸候选无
  `title_score` 而全部被淘汰；现在先补分再过滤（幂等）。

### A 阶段已暴露并修掉的真实问题

| 问题 | 现象 | 处理 |
|---|---|---|
| 循环依赖 | `import app.metadata` 直接失败，54 个测试连锁报错 | 抽出 `textnorm.py`，两边都从它导入 |
| 番外精确匹配过宽 | “女子落语OAD番外”被当成精确匹配，抢走主条目 | 包含匹配加长度上限（候选名 ≤ 2×本地名） |
| 正则 `\b` 对中文失效 | `OAD/OVA` 等词在中文标题里匹配不到，降权不生效 | 改用 `(?<![a-z])…(?![a-z])` |
| 决策器过滤早于打分 | 裸候选无 `title_score`，第一轮被全部淘汰 | `decide()` 先补分再过滤 |

> 这些问题都是拆分层之后、由新单测直接暴露的；此前混在 363 行 `match()` 里无法定位。

## 3. B 阶段：质量检查对象化 ✅

- 新增 `app/qc.py`：
  - `QcResult(code, message, severity, action)`：reason code + 文案 + 严重度 + 建议动作；
  - `QcReport`：汇总（去重、`worst`、`blocked`、`needs_review`、`summarize`）；
  - `status_for()`：由检查结果 + 置信度推导 auto/review/skip，规则与旧逻辑一致；
  - `CODE_LABELS`：原因码 → 界面短标签。
- `PlanItem.qc_codes`：任务携带结构化原因（`status`/`note` 继续保留，兼容既有界面）。
- `Planner._mark()`：统一记录原因，并按严重度把"自动"降为"需确认"。
- 已接入的判定点：

  | 原因码 | 触发场景 |
  |---|---|
  | `no_title` | 识别不出剧名/电影名 |
  | `no_online_title` | 联网拿不到标题 |
  | `search_term_too_short` | 搜索词只有单字/容器名 |
  | `low_confidence` | 置信度低于阈值 |
  | `season_title_conflict` | 季目录视频名与上级剧名冲突 |
  | `duplicate_episodes` | 同季同集多文件疑似重复 |
  | `season_unconfirmed` | 季号未确认，暂停集数改名 |
  | `special_unmatched` / `special_zero_guessed` | 特别篇补号 |
  | `bdmv_inner_dir` | 选中了 BDMV 内部目录 |

- 详情面板新增"原因：低置信度、疑似重复集 …"，由 `qc_codes` 直接渲染，
  不再解析备注文字。
- 新增 `work/tests/test_qc.py`（5 组用例）。
- **验收**：回归 **67 通过 / 1 环境失败**（`test_gui_real_listing`，依赖实时网盘数量）。

## 4. C 阶段：GUI 解耦 ✅

- `_build_ui()`（366 行）拆为面板方法，按构建顺序调用：

  | 方法 | 行数 | 内容 |
  |---|---|---|
  | `_build_ui` | 8 | 只负责依次调用下面几个 |
  | `_ui_window` | 20 | 标题、居中、最小尺寸、主题与 Treeview 样式 |
  | `_ui_top_bar` | 36 | 顶部按钮与更新提示条 |
  | `_ui_main_split` | 4 | 左右分栏容器（`self.paned`） |
  | `_ui_left_panel` | 87 | 文件来源、导航、目录树、右键菜单 |
  | `_ui_right_panel` | 214 | 任务表、详情、影片资料、日志 |
  | `_ui_status_bar` | 6 | 状态栏与收尾 |

- `_handle()`（154 行 → **5 行**）：改为 `KIND_HANDLERS` 路由表 +
  `_on_<kind>(payload)` 方法，24 个消息类型一个方法一个；新增消息只需加一行路由。
- 拆分过程中修掉两个搬运问题：分栏容器语句落在分区缝隙里没被搬走（`paned`
  未定义），以及局部变量跨方法不可见（改用 `self.paned`）。
- **验收**：67 通过 / 1 环境失败；GUI 交互类测试（冒烟、多选、编辑、预览、
  临时改名、NFO、缓存恢复、更新提示）全部通过。
