# 刮削与改名优化路线

参考对象：网易爆米花 `BaoMiHua-2.12.13.apk`（`com.netease.filmlytv`）。
只做了 APK 静态分析，没有调用网易线上接口，也没有复制其代码。

## 一、解剖结论

爆米花客户端主要负责：

- 扫描本地/网盘/SMB/WebDAV 文件；
- 上传文件路径、大小、时长、分辨率、类型；
- 展示服务端返回的电影/剧集/季/集结果；
- 提供人工搜索、季集映射和提交修改。

真正的元数据匹配、季集判断和合并逻辑在服务端。客户端代码中
没有 TMDB/豆瓣/IMDb 的直接抓取实现，也没有可复用的服务端算法。

可借鉴的是它的数据模型和纠正流程：

- 以 TMDB ID 作为主身份；
- 区分电影、剧集、季、集；
- 记录总集数、本季集数；
- 区分“本季第 N 集”和“总第 N 集”；
- 自动识别后允许人工搜索和逐文件季集映射；
- 检测重复集；
- NFO/字幕作为独立文件类型处理。

## 三、已完成

### 1. TMDB 季集结构

`MetadataClient.tmdb_detail()` 现在同时缓存：

- `seasons`：季号、名称、集数、首播日期；
- `number_of_seasons`；
- `number_of_episodes`。

新增 `tmdb_tv_structure()`，供 Planner 做季集校验。

### 2. 集数校验

- 明确写了 `Sxx`，但文件集号超过 TMDB 该季集数时，备注提示核对；
- 文件没有任何季标记，且集号超过 TMDB 第一季集数时：
  - 不默认归到 S01；
  - 标记“需确认”；
  - 暂停集数改名；
  - 提示可能是总集编号；
- 只有 TMDB 明确有两季以上时才启用，单季番剧不会误判。

### 3. 手动搜索结果增强

TMDB 搜索结果现在带：

- `country`：日本/中国/美国/英国/加拿大等；
- `first_air_date`：首播/上映日期；
- `overview`：简介；
- `vote_average`：评分；
- `poster_path`：海报路径（后续可做预览）。

手动搜索窗口选中结果后，下方显示这些信息，便于区分同名影片。

### 4. 手动季集映射

- 详情里新增“季集映射…”；
- 列出任务里的所有视频和推断季/集；
- 支持多选后设置季号 + 起始集，集号顺序递增；
- 支持“总集数自动分季”，按 TMDB 累计集数映射；
- 重复集用红色提示；
- 应用后只重建预览，不直接改网盘；
- `PlanItem.episode_overrides` 保存逐文件映射，重新生成预览时仍然生效。

### 5. NFO 元数据锚点

- 新增 115 只读下载方法 `download_bytes()`，限制 2 MB；
- 扫描目录时收集根目录的 `.nfo`；
- 剧集只读 `tvshow.nfo`（`season.nfo` 的标题通常是“Season 1”，不作为剧名锚点）；
- 电影优先读 `movie.nfo` 或与视频同名的 `.nfo`；
- 解析 `uniqueid type=tmdb/imdb`、`tmdbid`、`imdbid`、标题、年份；
- NFO ID 优先匹配，并用 NFO 标题做一致性校验；
- 电影库根目录多部电影时，只使用和当前视频名匹配的 NFO，避免张冠李戴；
- 解析失败自动退回原搜索流程。

### 6. 统一媒体身份

- 新增 `MediaIdentity`（媒体类型、TMDB/IMDb ID、标题、原名、年份）；
- `PlanItem.identity` 统一合并 `match`、`context`、人工标题/年份覆盖；
- 剧集文件夹名、电影 ID、英文名补全、NFO uniqueid、影片资料面板
  都改为从最终身份取 ID；
- 保留原字段兼容现有逻辑，没有一次性推翻 Planner。

### 7. 多版本/重复集检测

- 同一部剧/电影有多个版本目录时，按 TMDB/IMDb 身份 + 季集范围
  （电影按视频数）分组；
- 选一个主版本保留原名，额外版本的**文件夹名**在 ID 前加 `V2/V3`，
  例如 `测试剧 Test Show (2020) V2 [tmdbid-100]`；
- 文件夹里的视频正常命名，不加 `v2`；已有 `V2/V3` 的目录保留
  原编号；不同季（S01 与 S02）不会因为 ID 相同被误标；
- 只有一个目录时，同季同集多文件才进入文件级判断：
  - 两边都带规格且确实不同 -> 多版本，临时在视频名加 `v2` 防撞名；
  - 只有扩展名不同、或其中一边没有规格 -> 疑似重复/错集；
- 疑似重复仍生成预览，但任务降级为“需确认”并取消自动勾选；
- 季集映射窗口用蓝色标“多版本”、红色标“疑似重复”；修正映射后
  自动状态可以恢复，过期的重复提示会被移除。

### 8. 搜索结果地区/类型筛选

- 手动搜索窗口增加“类型、内容、地区”三个筛选；
- 类型：全部 / 剧集 / 电影 / 未知；
- 内容：全部 / 动画 / 真人 / 未知；
- 地区：日本 / 中国 / 美国 / 英国 / 加拿大 / 欧美 / 未知；
- Bangumi 搜索结果会自动补详情（30 天缓存）：补出地区，并用
  “剧场版/电影/映画”等标签把条目改成电影；
- 只使用来源明确提供的信息：TMDB 的 genre/country、Bangumi 的
  地区/标签、豆瓣标签、IMDb 的 movie/tvSeries；信息未知的结果不会
  被误标成真人或某个地区；
- 结果表新增“内容/地区”列；筛选提示行会显示被隐藏的未知项数量，
  可切到“未知”查看；筛选后可随时重置。

### 9. OAD/特别篇/第0集补全

- `OAD` / `SP` / `OVA` / `特别篇` / `Specials` 目录视为第 0 季；
- 任意目录里的 `SxxE00` 按 TMDB 特别篇的“第0话/第0集”映射为
  `S00E01`，不再因为“集号是 0”被跳过；
- 任意目录里带 `[Special]` / OVA / OAD / 特别篇 标记、但没有真正
  `SxxExx/EP/第N集` 标记的文件（包括蓝光 ISO）也进入特别篇匹配；
- 目录里的文件没有 `SxxExx` 时，先读取 TMDB 第 0 季单集标题；
- 用文件名里的中文标题、英文名、日文名/别名做模糊匹配（阈值 0.74），
  一对一分配 `S00E01`、`S00E02`…；
- 匹配不到的文件才按文件名自然顺序补空号；
- 若只剩一个未匹配文件、TMDB 也只剩一个未用集号，直接补上该唯一
  编号并保持自动；仍有多个可选编号时才降为“需确认”；
- 在线特别篇标题会去掉重复剧名后作为副标题；
- 字幕目录里 `00 (BDRip...).sc.sup` 这类编号也能解析，第 0 集字幕
  跟随到 `S00E01`，正片 `01` 不会被误配到 `S00E01`；
- 实测《君主·埃尔梅罗二世事件簿》：
  `S1E00.m2ts` → `S00E01.第0话…`，
  `[Special][JP].iso` → `S00E02.特别篇…`，
  `字幕/…00….sc.sup` → `S00E01….sc.sup`；
- OAD 不再出现“没有识别到集数，已跳过”。

### 10. 合集内嵌季目录发现

- 合集根目录同时有散装电影和季目录时，不再只分析根目录视频；
- 对根目录下的子目录做轻量探测：
  - 子目录直属视频 ≥2 个，且至少 2 个带集号（SxxExx/EP/第N集）；
  - 目录名带 BDMV/Vol/Season 等介质提示，或与合集根目录同属一部片；
  - 字体、字幕、花絮、BDMV 内部目录不进入；
- 通过探测的子目录递归分析，并标记为独立季目录；
- 即使目录名没有 Sxx，也会从文件里的 S1E01/S2E01 得到季号，
  文件夹名补上 `S01`/`S02`；
- 最外层合集目录仍作为容器保留原名，散装电影保持独立电影任务；
- 实测《希德尼娅的骑士》合集：
  - 根目录两部剧场版 ISO → 2 个电影任务；
  - `[希德尼娅的骑士][BDMV][Vol.01-06]` → S01，12 集；
  - `[希德尼亞的騎士 第九行星戰役][BDMV][Vol.1-6]` → S02，12 集；
  - 新文件夹统一用 `[BD-REMUX]` 开头，不沿用原目录的 `[BDMV]`；
  - 字幕目录里 `[05(New Angle Ver.)]` 这类编号也能跟随改名；
  - `S2-美版暂无日语字幕sup` 这种“季号+说明”目录归到 S02，
    不再单独生成一个用说明文字当剧名的任务。

### 11. 四来源固定显示

- 手动搜索不再用“来源”下拉框，改为固定按钮：
  `全部 / 豆瓣 / Bangumi / IMDb / TMDB`；
- 每个按钮显示该来源当前结果数，例如 `IMDb (9)`；
- 搜索时始终同时查询全部可用来源，切换按钮只过滤当前结果，
  不会重新联网；
- 来源筛选与类型/内容/地区筛选可以叠加；
- 重置筛选会回到“全部”。

### 12. 搜索词拆解与误配防护

- 中文名后面的英文/数字后缀不再被切掉：
  `攻壳机动队 SAC 2045` / `攻壳机动队 SAC_2045` 都以完整标题搜索；
  带 `Part.2`、`Season 2`、`S02` 的标题同样保留；
- 中文名后只是纯英文别名时，仍取中文主标题，但把完整中英串
  保留为搜索候选（例如 `希德尼娅的骑士 Knights of Sidonia`）；
- `01.m2ts`、`02.m2ts`、`01`、`02` 这类纯文件名/序号不再进入
  元数据搜索词，避免用文件序号去匹配作品；
- 手动搜索关键词改为**本地优先**：
  1. 用户手动改过的标题；
  2. 当前目录解析出的完整标题；
  3. 最近的上级目录（跳过“动画/日本”等容器名）；
  4. 自动匹配的标题/原名/别名只在与本地主标题一致时补充；
- `S2-美版暂无日语字幕sup` 这类季目录先从上级目录取作品名，
  说明文字不再成为关键词；
- 关键词在界面上用普通文字显示，以 `·` 分隔，可点击换词，
  不再使用一排按钮；
- 实测《攻壳机动队 SAC 2045》：
  - 解析标题为 `攻壳机动队 SAC 2045`，搜索词不含 `01.m2ts`；
  - 正确匹配 TMDB 90293 / IMDb tt13236336；
  - S1 与 `S2-美版暂无日语字幕sup` 合并为同一任务，季列表 `[1, 2]`；
  - 第二季文件正确输出 `S02E01`，不再生成“美版暂无日语字幕sup”任务。

### 13. 左侧文件/文件夹右键改名

- 左侧目录树右键单个文件/文件夹，菜单新增
  “重命名此项（立即生效）…”，也可以按 F2；
- 右键菜单同时提供“进入文件夹”“分析选中”“刷新当前目录”；
- 改名对话框预先填入原名并全选，直接输入即可替换；
- 文件没写扩展名时自动补回原扩展名；扩展名不一致时拒绝提交
  （115 不允许修改扩展名）；
- 同一目录内已有同名项目时先在本地拦下；
- 确认后只调用一次 115 批量改名接口，只改这一项，
  不删除、不移动、不新建；
- 成功后：
  - 左侧列表自动刷新并重新选中改名后的项目；
  - 写入撤销记录，可用“撤销上一次”恢复；
  - 右侧等待任务里同一 fid 的旧名称同步更新，
    避免后续批量应用按旧名失败；
- 改名失败时保留原名，并在界面和日志里显示 115 返回的错误。

### 14. 应用改名后自动保存 NFO

- 详情里的 NFO/图片按钮旁新增可勾选项
  “应用改名后自动存 NFO/图片”，状态写入 `settings.json`
  （`auto_nfo_after_rename`），下次启动仍保留；
- 勾选后，点“应用选中重命名”的确认框会明确提示
  “完成后会自动保存 NFO/图片”；
- 改名全部成功后，在同一个后台任务里继续对相关任务执行
  和“保存 NFO/图片”完全相同的流程：
  - 获取影片资料、海报、背景图；
  - 生成 tvshow/每集/movie NFO；
  - 已有 NFO/图片按设置“跟随改名”或“删除后重存”；
  - 上传到 115 对应目录；
- 如果某个任务有文件改名失败，不自动保存该任务的 NFO，
  避免按不存在的名字生成资料；结果提示会列出原因；
- 自动保存失败不吞错：重命名结果和 NFO 错误分开显示，
  方便重新分析后手动保存；
- 演示模式下即使勾选也只模拟改名，不会上传 NFO/图片；
- 关闭勾选后恢复原来的行为：改名完成清空等待列表，
  NFO/图片仍由“保存 NFO/图片”按钮手动执行。

### 15. 115 风控保护

- 请求间隔：
  - 普通读取（列目录、查详情）约 0.45 秒；
  - 写入（批量改名、删除）约 1.15 秒；
  - NFO/图片上传初始化约 1.3 秒，上传文件本身再停 0.6 秒；
  - 所有间隔都加 0–0.2 秒随机抖动，避免固定节奏。
- 批量大小：
  - `batch_rename` 每批最多 10 项（原 20），两批之间随机停 1–1.8 秒；
  - 移入回收站每批最多 20 项（原 50），同样有批间停顿。
- 风控识别：
  - HTTP 403/429、`Retry-After`、返回文本包含
    “频繁/过快/风控/风险/验证码/限制/too many/rate limit”等，
    统一视为风控；
  - 立即停止当前批次和后续批次，剩余项目标记失败，
    不再继续请求；
  - 进入 60 秒冷却（服务端给了 `Retry-After` 时按服务端值，30–180 秒），
    冷却期内所有 115 请求直接拒绝，不发网络请求；
  - 同一会话再次触发风控时，冷却时间按 1.5 倍递增（最多 180 秒），
    读取/写入/上传间隔也自动再放慢；
  - 界面日志和错误框会说明剩余冷却时间和新的请求间隔。
- 登录保护：
  - HTTP 401、明确的“登录已失效/未登录/被踢下线”才判定为登录失效；
  - 网络异常、5xx、JSON 异常不再被误判成登录失效，不会反复弹扫码；
  - 登录失效提示会建议换设备类型（ios ↔ web），避免同类型互踢；
  - 扫码/导入 Cookie 成功后清除冷却状态。
- 自动 NFO：
  - 上传逐个排队、逐个限速；
  - 遇到风控或登录失效立即停止后续任务的自动保存，
    已成功的改名仍保留可撤销。
- 读请求在网络异常/5xx 时最多自动重试一次（带退避）；
  写请求不盲目重试，避免重复改名或放大风控。

### 16. 进度条位置与分阶段显示

- 进度条从底部状态栏移到“等待处理的任务”右侧、任务表上方；
- 已知总数的任务统一使用 determinate 模式，不再用不确定动画来回抽动；
- 分析阶段显示：
  - “正在扫描目录…”（总数未知时只更新文字，保留当前进度）；
  - “正在准备分析…”；
  - “正在分析：某目录（读取目录/联网查询）”，按媒体根目录推进；
- 重命名阶段显示“阶段 1/2：正在重命名…”，按实际批次 x/y 推进；
- 自动保存 NFO 阶段显示“阶段 2/2”：
  - 先准备资料/读取已有 NFO；
  - NFO 文件总数确定后，把它加到重命名进度之后，
    进度条不会先归零再重跑；
  - 每个 NFO/图片上传、跳过、旧图改名都会推进真实计数；
- 手动“保存 NFO/图片”也显示获取资料、读取目录、上传 x/y；
- 总数未知的阶段只更新阶段文字，不把已有进度清掉；
- 任务结束/出错时统一清空进度条和阶段文字。

### 17. 重命名预览逐项勾选

- 预览表新增“选”列，默认全部勾选；
- 点击“选”列可单独取消/恢复某个文件夹、季目录、视频或字幕；
- 底部显示“已选 N/M”，并提供“全选/全不选”；
- 勾选状态保存在 `RenameOp.selected`，关闭预览后仍然有效；
- 应用选中重命名时只收集勾选的项目：
  - 未勾选的文件夹/文件保持原名；
  - 不会再因为未勾选项产生同名冲突；
- 自动保存 NFO/图片也只跟随勾选项目：
  - 用只含勾选 op 的浅拷贝生成 NFO；
  - 上下文 entries 也按勾选视频过滤；
  - 未勾选视频不会生成 NFO，也不会被“删除后重存”误删；
- 重新分析/重新生成预览会创建新的 op，默认恢复全选。

## 四、验收标准

- 额外版本目录的文件夹名带 V2/V3，视频文件名保持正常；
- 同一目录内同集多文件不能互相覆盖，预览中能看出临时 v2；
- 疑似重复必须降低自动化等级，不能混在“自动”任务里直接批量应用；
- 手动搜索筛选不能凭空猜测未知地区/类型；
- 搜索词不能包含 `01.m2ts` 这类文件序号，也不能让匹配错的别名
  覆盖本地完整标题；
- 左侧右键改名必须二次确认、扩展名不变、只改这一项，并写入撤销记录；
- 自动保存 NFO 必须由用户提前勾选，确认框明确提示；
  部分改名失败的任务不能自动生成 NFO；
- 触发 115 风控后必须停止后续写请求，冷却期内不得继续发请求；
- 进度条必须反映真实阶段/计数，不能用不确定动画冒充进度；
- 预览默认全选；取消勾选的项目不得改名，也不得生成对应 NFO；
- 网络异常不得直接判定登录失效、不得反复触发扫码；
- 关键词只影响搜索/筛选，不修改元数据、不改网盘。

## 五、边界

- 不调用爆米花私有接口；
- 不使用其账号、密钥或官方豆瓣授权；
- 不复制反编译代码；
- 只独立实现相同思路的功能。
